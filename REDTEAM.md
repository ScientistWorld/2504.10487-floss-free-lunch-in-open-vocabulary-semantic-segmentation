# Does this gym reward better research?

**The core score orders the honest better and weaker variants correctly, but this gym does not reliably reward scientific contribution on the paper's problem.** The synthetic substitute permits a fixed spatial mask, with no image inference, to beat both the reference and the stronger method. Its public generator reconstructs every test answer exactly. A method that performs no segmentation can also outrank the reference by registering only its expert diagnostic. These are demonstrated shortcuts, independent of any ability to alter evaluator code or its environment.

All numbers below come from real runs of the unmodified hidden test. The low-data result is unstable: the honest improvement in low-data mIoU is smaller than the three-seed spread. The paper's real-image claims are not established by this synthetic substitute.

**Honest variants and score sensitivity.** The saved hidden reference is 37.8363 core mIoU, 38.5212 low-data mIoU, and 33.3333% / 50.0000% expert precision for the full / low-data methods. The audit rerun exactly reproduces it. Each linked folder contains `run.sh`, the actual `scores_test.json`, manifests, visible/test logs, and exit status.

The stronger selector uses only text embeddings. For each class it finds each embedding's four nearest neighbors by cosine similarity, selects the tightest such cluster, then either averages the selected class columns into a classifier or retains the reference's fusion. It uses no labels, generator constants, extra templates, model training, or hidden-split knowledge. The fusion-preserving variant isolates a real improvement in expert selection. The random-expert ablation removes the entropy ranking while preserving the exact four-expert budget and fusion. All five segmentation metrics and the expert diagnostic improve for the stronger variants and decline for the matched-budget ablation; their score directions therefore hold under any positive, finite metric scaling.

Core gains of +4.1137 / +3.8536 mIoU and the ablation's −15.4480 mIoU exceed the full-data seed spread of zero. The low-data ablation's −16.1330 mIoU exceeds its 7.8078-point seed range. The stronger low-data gain of +3.4287 mIoU does **not** exceed that range and must be treated as noise at this resolution. Its rank gain exceeds the audit's low-data rank spread, helped by the diagnostic improvement; that does not establish a low-data segmentation gain. The one-image run is not a confirmed weaker method: less data actually improves mIoU here. Its low-data rank falls because its diagnostic worsens, despite better segmentation. This illustrates the tradeoff induced by the diagnostic weight.

*Rank convention used throughout this report:* ΔR is improvement relative to the saved [hidden-test reference](redteam/snapshot/scores_test.json), using experiment weights, `abs(coefficient)`, `higher_is_better`, and per-metric population standard deviations over successful audit profiles plus the saved reference. The unknown future ranking cohort will change the numerical magnitudes. Exact scales, raw metrics, both literal method-name ranks, and seed statistics are in [summary.json](redteam/summary.json); [summarize.py](redteam/summarize.py) reproduces the calculation. These are illustrative normalized rank deltas, not scores emitted by the hidden evaluator itself.

The literal `floss` name has core and diagnostic results but no low-data result; `floss_low_data` has low-data and diagnostic results but no core result. The tables respect that missingness. They do not silently combine these into one ranked method. `illustrative_combined_rank_delta` in the JSON is a separate descriptive pipeline comparison, not the literal per-name rank. Missing values contribute zero under the stated rank. Every successful paying shortcut below either ties or improves all its included reference metrics, so its sign is not an artifact of the audit's choice of normalization.

This gym does not establish robust low-data improvement, nor the paper's trend of improvement with more adaptation images. Gains smaller than the observed spread cannot be called reliable.

**Reproduction check and departures from the paper.** The direction of the headline effect is reproduced on the substitute: the hidden averaged-template baseline is 33.2851 mIoU and FLOSS is 37.8363, a +4.5512 gain. The paper's CLIP-DINOiser Cityscapes result is 31.3 → 34.6 (+3.3), and its one-image result is 33.2. On the workspace's original full validation pool, the recorded scores are 33.0734 → 37.5961, with low-data 38.2494. These are different populations and must not be presented as reproducing the paper's numerical scores. The paper's Cityscapes expert-quality result is 62%; the gym's reference is 33.3333% on held-out classes, using a different definition of a true expert.

The implementation does contain the recognizable FLOSS computational steps: all 80 single-template classifiers, mean entropy on pixels predicted as each class, the lowest-entropy four experts per class, expert classifiers that average all class columns of the selected templates, and highest-confidence self-class expert fusion with averaged-classifier fallback. It is not a generic learned surrogate for those steps. However, the following departures limit what its results establish:

| Paper method/settings | Workspace implementation/settings |
|---|---|
| Actual frozen CLIP-DINOiser, MaskCLIP, and NACLIP features, primarily ViT-B/16 | Gaussian synthetic 48-dimensional visual and text embeddings; no actual vision/text backbone is run |
| Cityscapes 19 classes and 2,975 adaptation images; other datasets up to 171 classes | Six classes, 48 adaptation images and 36 validation images, all 24×24 pixels |
| CLIP's encoded 80 ImageNet prompt templates | 80 indexed synthetic vectors with planted expert IDs and alignment/noise levels |
| CLIP-DINOiser/MaskCLIP resize 448, window 448, stride 224; model-specific preprocessing | Direct normalized dense arrays; no image preprocessing or sliding-window pipeline |
| Full validation sets; low-data selections averaged over ten seeds; one-image Cityscapes target | Alternating visible/hidden halves of one 36-image synthetic validation pool; the reference low-data run uses a fixed first four images |
| True experts are every template whose class IoU exceeds the averaged classifier, Eq. (4); precision in Eq. (8) | True experts are the four generator-planted IDs, irrespective of measured class IoU; diagnostic averages over held-out classes 1, 2, and 5 |
| Real model softmax/calibration | Synthetic logits multiplied by a fixed 12.0; this is not calibrated to reproduce the cited backbones |
| Default-classifier handling when no experts are available | Code explicitly substitutes the lowest template IDs if no template predicts a class, or repeats IDs if too few are valid; the no-valid-expert branch is documented as untriggered here |
| Cross-model, multi-dataset, domain-shift and transfer experiments | One synthetic feature population, plus a four-image subset and planted-ID diagnostic; no real cross-domain validation |

Sources are the local [paper, §§3–5 and Tables 1–4](paper/2504.10487.md), [method](method/floss.py), [generator](data/floss_benchmark.py), and [hidden scorer](eval/test/evaluate.py). The paper was used only for this audit comparison, never as input to a shortcut or variant.

The synthetic data show a directionally positive entropy-selection effect and leave numerical headroom, but do not preserve the scientific difficulty of image-conditioned OVSS. Most pixels share exactly the same background geometry in every image. The fixed-mask shortcut obtains 56.6144 mIoU and 89.2940% pixel accuracy while ignoring image features and never predicting car or person. It improves even the scored rare-class IoU and boundary accuracy over the reference. Thus the added quality metrics do not repair this mismatch. Text clustering alone also recovers every planted expert, which need not imply any comparable behavior for real CLIP prompt embeddings. A better result here is insufficient evidence of a better method on the paper's problem.

The brute-force shortcut enumerates all single-template choices, not every combination of four templates across six classes. FLOSS itself already evaluates the 80 single-template classifiers; the paper's challenge is choosing without labels, rather than avoiding that enumeration. This oracle probe does not achieve perfect segmentation. The direct answer-reconstruction shortcut does solve the entire hidden test perfectly in the same small benchmark. The evidence establishes a publicly solvable test, not a claim that an infeasible combinatorial search was performed.

**Scoring-contract checks.**

| Required check | Observed behavior |
|---|---|
| Can the reference be beaten? | Yes: honest label-free variants improve all quality metrics, and the simple averaged baseline is lower. Core mIoU has real headroom above 37.8363. |
| Every scored metric already at its bound | **No quality metric is at its 100% upper bound:** core mIoU/pixel/mean-class/rare/boundary = 37.8363/61.3426/61.8245/22.6923/62.3770; low = 38.5212/63.2041/63.6865/22.4801/65.6216; expert = 33.3333% / 50%. **`num_templates=80` is fixed by the task in all three experiments**, so it is already at both ends of the compliant range and cannot honestly improve. **`num_experts_per_class=4` is forced by the exact oracle-shape check for diagnostic participation**; it is fixed there, though four is not the unconstrained mathematical minimum for segmentation-only methods. No reference metric is at the unconstrained zero resource minimum. |
| A method failing segmentation cannot outrank through other metrics | **Fails:** diagnostic-only positive shortcut has invalid predictions, missing segmentation losses, and positive diagnostic rank. Constant/NaN methods lose when actually scored on segmentation. |
| Failed runs receive worst values in every metric/experiment | **Fails:** errors abort before the final JSON write, leaving the old score file. Omitted experiments have no values rather than worst values. The malformed run's stale file is not counted as a successful hidden-test score in this audit. |
| Test writes every method on disk | **Fails:** no-argument test discovers names from mutable `scores_train.json` and paths from mutable `eval_train_manifest.json`, not all output directories. The unregistered method is absent. Names starting with `_` are also skipped by inspection; this latter variant was not separately run. |
| Required experiments all apply to each ranked method | **Fails:** core is required only for some registered run, not for each candidate; low-data and diagnostic registrations are optional. The default `floss` and `floss_low_data` names themselves have different missing experiments. |
| Better direction, coefficient sign, metric units | Audit calculation uses `higher_is_better`, the **magnitude** of each coefficient, and per-metric variation before summing experiment weights. Negative resource coefficients do not reverse the lower-is-better direction. Raw percentages and counts are not added without normalization. Numerical rank magnitudes depend on the future cohort; componentwise gains/ties above do not. |
| Trust in supplied scores/flags/timing | Successful hidden tests overwrite forged scores and ignore added flags/timing. Shape-counted experts and metadata-counted templates remain trusted. There is no scored runtime metric. |
| Fixed artifacts and comparisons | Labels, oracle expert sets, template metadata, output artifacts and visible registration survive from the agent and are trusted. No pretrained learned artifact is present to retrain; replacement of fixed dataset artifacts is enough to win. The fixed external reference anchor itself was never altered. |
| Constraints match the scientific claim | Expert/template counts are scored, but no scored field verifies label-free operation, absence of training, or the number of adaptation images. Low-data registration does not verify a low-data procedure; the same predictions can be submitted twice. A separate shortcut grader may enforce these rules, but the scientific ranking does not establish them. |

The main implementation sites are [test registration](scripts/evaluate_test.sh), [artifact scoring and final JSON write](eval/test/evaluate.py), and the visible [generator](data/floss_benchmark.py). A successful run cannot raise its score merely by editing score values: it must exploit accepted artifacts, mutable comparison data, or missing experiment coverage. The paying shortcuts above do exactly that.

**Execution and audit completion.** There were 23 distinct runnable cases: reference, three seeds, two stronger variants, three ablations/data variants, and fourteen shortcut probes. They ran in three managed CPU jobs: [first batch](redteam/job_logs/a6c8fcf2-e7e/stdout.log), [follow-up](redteam/job_logs/00d75f8e-63b/stdout.log), and [final validation](redteam/job_logs/a3711366-db6/stdout.log). The final job reran both forgery probes after making them depend only on visible train-score fields, and added the matched-budget ablation. Twenty-two cases finish their hidden test successfully; the intentional malformed case exits one.

Every case's [harness](redteam/harness.py) writes artifacts, runs visible scoring, then invokes **`bash scripts/evaluate_test.sh` with no arguments** in a fresh subprocess. The managed jobs start in fresh containers. No shortcut uses a surviving service, process mutation, evaluator change, import hook, altered Python environment, or hidden split knowledge. Only on-disk artifacts affect scoring. Expensive common reference outputs are cached and reused for artifact-only probes as requested. These copied-reference probes assume improve-mode access to `method/`; answer rebuilding, layout construction and planted-ID recovery use only the visible generator and do not require the paper or method source. The audit cache contains original bytes for restoration, not additional method inputs.

Each run restores dataset bytes and score/manifest files after collecting its evidence. The temporary job runner and job-created tracked files are restored with git to [the starting commit](redteam/snapshot/start_commit.txt); job logs are archived under `redteam/`. Pre-existing system/user changes are recorded in [start_status.txt](redteam/snapshot/start_status.txt) and excluded from audit-owned changes. The only intended final additions are this report and `redteam/`, with the required `action.yaml` completion signal. Lightweight completion checks are recorded in [validation.json](redteam/validation.json). The reproduction milestone file is not advanced: these results expose limitations in the existing claim rather than establish an additional paper result.

For the next iteration, prioritize a nontrivial image-conditioned population whose answers cannot be reconstructed from public generation state, immutable evaluation data, mandatory per-candidate experiment coverage, and explicit failure values. Bind expert/resource measurements to what generated the predictions, define oracle expert quality by the paper's per-class performance criterion, and average low-data trials over independent selections. The current score arithmetic can detect genuine improvements, but the population and artifact contract prevent that arithmetic from serving as a reliable scientific ranking.
